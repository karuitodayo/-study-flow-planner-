> **本資料について**
> 「要件定義書」の原本はプロジェクトフォルダ内に見つかりませんでした（Git履歴・CHANGELOGも存在しません）。
> そのため本資料は、原本の要件定義書ではなく、**現在のソースコード・コード内コメントのみを根拠に実装仕様を整理し直したもの**です。
> 推測で補った記述は行わず、コードから確認できない点はすべて「未確認」と明記しています。

---

## 1. ツールを制作した目的

学習・勤務・案件（デザインコンペ／受注案件）を1つの画面で管理する、個人用の学習支援ダッシュボード。
AI学習の時間確保を軸に、勤務シフトや案件の締切と衝突しないように学習スケジュールを自動生成することが中心的な役割。

（出典: `app.py` 冒頭docstring、`pages/3_カレンダー.py`、`pages/7_案件管理.py`）

## 4. 制作途中で追加・変更した機能

### 4-1. 確認できる修正（コード内コメントに経緯が残っているもの）

Git履歴・CHANGELOGが存在しないため、ソースコード中に修正の経緯として残っているコメントのみを根拠にしています。

1. **ドリル管理の情報編集を1画面に統合**
   旧「情報の一括編集」タブを廃止し、チェックリスト・教材情報・進捗編集をすべて詳細モーダル（`st.dialog`）に集約した（同じ情報を複数画面で入力する必要をなくすため）。

2. **ドリル削除を論理削除（アーカイブ）に変更**
   削除時に行自体や関連する学習記録・タスク・カレンダー予定を消さないよう変更し、一覧から非表示にするだけでいつでも復元できるようにした。

3. **カレンダー詳細パネルの操作ボタンをポップアップに統合**
   以前は選択中の予定の操作ボタン（固定/完了）を一覧の下に別行・全幅で表示していたため、どの予定に対する操作か分かりにくく、完了済みの予定では「固定」ボタンだけが単独で浮いて見える問題があった。各予定の「…」ポップアップメニューにまとめて解消した。

4. **学習記録（日報）の振り返り項目を統合**
   旧項目（できたこと・うまくいかなかったこと・改善メモ）を「1日の振り返り」に統合し、既存データは「過去に記入した旧項目の内容」として参考表示に残す形にした。

### 4-2. 初期要件への言及がなく、追加された可能性がある機能

上記「2.」で挙げた、コード内に「要件◯章」の言及がない機能（目標管理・案件管理・シフト登録・学習タイマー・PDCA日報など）は、後から追加された可能性があります。ただし、単にコメントが付けられなかっただけの可能性も残るため、**断定はできません（未確認）**。

## 5. 各機能で使用している主な技術

| 区分 | 技術 | 用途 |
|---|---|---|
| アプリケーションフレームワーク | Streamlit | マルチページのWeb UI（`pages/*.py`） |
| データ保存 | SQLite | 全データの永続化（`database/db.py`） |
| 外部連携 | Google Calendar API（OAuth 2.0、読み取り専用） | 勤務予定・私用予定の同期（`services/calendar_service.py`） |
| 画像認識 | Tesseract OCR（`pytesseract`） + OpenCV（`opencv-python-headless`） | シフト表画像からの勤務区分読み取り（`services/shift_ocr.py`） |
| カレンダーUI | `streamlit-calendar`（FullCalendarのStreamlitラッパー） | 月/週/日表示のカレンダー描画（`pages/3_カレンダー.py`） |
| PDF生成 | `reportlab` | 日報のPDF出力（`services/daily_reports.py`）。日本語フォントはWindows同梱フォント→同梱フォント→reportlab組み込みCIDフォントの順に自動検出 |
| データ集計・表示 | `pandas` | 週次振り返りのグラフ表示、設定画面のテーブル編集 |
| 設定管理 | `python-dotenv` / `PyYAML` | 環境変数・設定ファイルの読み込み |
